The Machine · 15-minute thesis

Onboarding takes weeks because of judgment calls, not pipes.

The answers live in Slack, get hardcoded into SQL, and disappear. The product is the decision that survives.

Then a live walkthrough. Interrupt whenever — I left the room for that.

1 · Problem

The weeks are spent answering questions the warehouse cannot see.

  • Does Meta spend include platform fees? Does Google cost include them?
  • Is this conversion last-click 7d/1d-view, or modelled 30-day?
  • Daily vs weekly grain: a join is already a decision, not a SQL problem.
  • Those answers get hardcoded into pipeline logic. Next quarter, nobody knows who decided, or why.
2 · Solution

Land. Resolve. Serve. Only the middle is the product.

Land · buy

Get the files in

Connectors, auth, warehouses. Commodity. Stubbed on purpose.

Resolve · the product

Ratify a semantic contract

Map → detect → adjudicate. Author, timestamp, version. Diffable in git.

Serve · payoff

Query with caveats

The number carries its own disclosure. An agent that skips the caveat is the failure mode.

The money slide

Harmonization without provenance is data laundering.

A 7-day-click conversion and a data-driven conversion are not the same event. Summing them produces a confidently wrong number an agent then acts on.

  • Detect the disagreement — don’t average it away.
  • Decide once, with a name and a timestamp on the decision.
  • Carry the caveat on the result object, not as a footnote someone might skip.
3 · Assumptions · product bets

Four things that have to be true for this to be a product.

1. Judgment is the bottleneck, not extraction.

Connectors exist. The weeks are fees, attribution windows, grain. Those answers currently die in Slack.

If wrong: this is a pipeline company. Stop. Buy Fivetran.

2. The deliverable is a contract, not a pipeline.

A pipeline does not compound. A versioned YAML with decided_by / decided_at is reviewable, diffable, and reusable as a prior.

If wrong: we are selling hours. Client two is not faster than client one.

3. ~15 canonical metrics cover ~90% of agent questions.

The hard work is not metric #16. It is recording how each source differs — disclosure axes on the canonical definition.

If wrong: the ontology becomes the product, and we drown in vocabulary.

4. Some conflicts are irreducible.

Two platforms measuring different events. The correct behavior is BLOCK: refuse a harmonised number until a human picks.

If wrong: just transform and sum. That is how you ship silent wrong answers.

3 · Assumptions · operating bets

How we refuse to cheat.

5. The taxonomy doc is evidence, not authority.

Docs go stale. Ours asserts naming and spend rules the exports violate. Where doc and data disagree, report it — do not silently pick a side.

If we treat the doc as truth, we automate the lie.

6. Unknown is a first-class output.

Never guess an attribution window or fee-inclusion rule. Guessing is how caveats disappear.

A mapping layer that always fills the field is a mapping layer that lies.

7. The model notices. Python is the policy floor.

Schema scan scales with the ontology. The agent finds what rules cannot see. The agent may raise severity; it may not AUTO two attribution windows.

If the model can quietly AUTO an irreducible definition, the rails are theater.

8. Client two must be faster than client one.

Resolutions become priors — field-name patterns and definitional defaults. Client data never crosses tenants. Entity resolution across ID spaces is out of scope.

If it doesn’t compound, this is an agency service, not a platform.

4 · Architecture

An agent with rails, not if-statements and not a black box.

AUTO

Deterministic transform

Micros → currency. Apply, log, don’t stop the human.

REVIEW

Reconcilable with loss

Daily vs weekly. Roll up, or keep split. Decide with a default.

BLOCK

Irreducible definition

Attribution model/window. Mixed currency. Do not sum.

Schema scan — no LLM

Collision groups × disclosure axes in metrics.yaml. Add an axis, get a new conflict class. No new if-statement. Grain, units, coverage come from the profiler.

Agent — tools, then Python

Finds what the schema cannot see: doc vs data, naming, entity-scope. Python raises to the floor. The model is allowed to notice. It is not allowed to AUTO a BLOCK.
